# Solana + Android (Expo) development notes

Hard-won notes from building **Nod**: Expo SDK 57, React Native 0.86 (Hermes), Android only, a Fastify backend, an npm SDK. Treat versions as a snapshot: **always check current Expo docs** (`https://docs.expo.dev/llms.txt`) before touching an Expo or RN API, and use `npx expo install <pkg>` (never `npm i`) so versions match the SDK.

## 1. Machine setup (macOS)

- Install Android Studio, then the SDK, platform-tools, build-tools and the **NDK** version the project asks for. Set `ANDROID_HOME=~/Library/Android/sdk` and put `platform-tools` on `PATH`.
- Phone: enable Developer options, USB debugging, plug in, accept the RSA prompt. `adb devices` must list it as `device` (not `unauthorized`).
- **Slow or hanging Gradle downloads** (IPv4 timeouts): run Gradle with
  `JAVA_TOOL_OPTIONS="-Djava.net.preferIPv6Addresses=true"`. If the SDK manager stalls, download the SDK/NDK zips with `curl` and unpack them into the SDK folder by hand. Raising the connection timeouts in `~/.gradle/gradle.properties` also helps (`systemProp.org.gradle.internal.http.connectionTimeout=30000`).
- Gradle builds take many minutes the first time. Run them in the background or let the user run them; do not block on them.
- `android/` is generated by `npx expo prebuild --platform android`. Keep it git-ignored; change native behaviour through `app.config.ts` and **config plugins**, never by hand-editing `android/` (it gets overwritten).

## 2. Dev loop

- Use a **dev client** (`npx expo run:android`), not Expo Go, once you use native modules (secure-store, local-authentication, notifications, MWA).
- Metro hot reload for JS. Over USB: `adb reverse tcp:8081 tcp:8081` (Metro) and `adb reverse tcp:3000 tcp:3000` (your backend), then the phone reaches your Mac at `http://localhost:…`.
- **Debug builds accept `http://`; release builds should refuse it.** Gate with `__DEV__`.
- Screenshots: `adb exec-out screencap -p > shot.png`. The screenshot is often scaled (for example 1080x2400 shown at 900x2000), so multiply coordinates by the scale before `adb shell input tap`.
- If you automate taps: write a guard script that refuses to tap unless your app is the foreground window (`dumpsys window | grep mCurrentFocus`), and take a screenshot after every tap. Blind taps have hit the wrong app.
- `ScrollView`/`FlatList`: set `keyboardShouldPersistTaps="handled"`, otherwise the first tap after typing only dismisses the keyboard.

## 3. App structure that worked

- State-based navigation in one shell (tabs + overlay screens) was enough; add the Android back-button handler (`BackHandler`) for every overlay.
- Persist small things in `expo-secure-store`, wrapped in a tiny `kv` helper; always wrap in try/catch.
- Theme: define colour tokens once, a `useColors()` hook, a system/light/dark preference. A light-on-white logo can be blended into an off-white page with `mixBlendMode: "multiply"` on a wrapping **View** (not on the Image: the type only allows it on ViewStyle).
- Biometrics (`expo-local-authentication`): Android has **strong** (fingerprint) and **weak** (camera face unlock) classes. Let the user choose, always keep screen-lock as a fallback, and warn when there is no backup.
- Push: `expo-notifications` + FCM. `google-services.json` is baked into the APK at build time and is not secret, but **do not commit it**; the *service-account* JSON used by the backend is the real secret. FCM tokens only work with the Firebase project they came from, so other people's backends cannot push to your APK. Send a **generic payload containing only an id**, never amounts or addresses. Clear the last notification response on launch or it replays every time.
- Hermes quirks: `Uint8Array.prototype.subarray` can return a plain Uint8Array without the extra methods you expect. Write a regression test that simulates it.

## 4. Icons, splash, package

- `icon.png` 1024x1024. Adaptive icon foreground 1024x1024 on a solid `backgroundColor`: Android masks it to a circle, so keep the artwork **inside ~46% of the canvas** (the safe zone is about 66% of the diameter). Splash image 1024x1024 with `imageWidth` in the plugin config; ~50% fill. Favicon 48x48.
- Changing icons needs `npx expo prebuild --platform android` (and a rebuild); Metro will not refresh them.
- Package id (`android.package`) is permanent once users have it.

## 5. Release APK

1. Generate your own key once and **back it up** (losing it means you can never update the app for existing users):
   `keytool -genkeypair -v -storetype PKCS12 -keystore ~/.signing/app-release.keystore -alias app -keyalg RSA -keysize 2048 -validity 10000`
2. Keep the keystore **outside the repo**. Put the path and password in `~/.gradle/gradle.properties`, not in the project.
3. Make signing survive `prebuild` with a **config plugin** (`withAppBuildGradle`) that adds a `release` signing config when the property exists and falls back to the debug key otherwise.
4. Bump `android.versionCode` for every release; Android refuses lower numbers. Same key + same package = users can install over the old version and keep their data. Changing the key later forces an uninstall.
5. Build: `cd android && ./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`.
6. Verify: `apksigner verify --print-certs app-release.apk` (must not say "Android Debug") and publish `shasum -a 256`.
7. A release APK is standalone (JS bundled), refuses `http://`, and cannot reach `localhost`. **Judges and testers need a reachable https backend**, or a server address built in.
8. No OTA updates unless you add `expo-updates` (and accept that an update channel can change app code).

## 6. Solana on mobile

- **Mobile Wallet Adapter 2.0** (`@solana-mobile/mobile-wallet-adapter-protocol`): `transact(wallet => wallet.authorize({ chain, identity, auth_token }))`. Cache the `auth_token` and re-authorize silently; fall back to a fresh authorize.
- **Phantom** will only re-authorize silently for an app whose identity is **verified** (Digital Asset Links on the `identity.uri` domain). Unverified apps get a Connect prompt on every transaction. This is a wallet policy, not a bug. `identity.icon` must be a **relative** path (an absolute URL gives `-32602`) resolved against `identity.uri`, so the favicon only shows once `uri` is a site that serves it.
- Backing out of the wallet surfaces as errors like "Cannot send in CLOSED". Classify wallet errors and make user cancellation a **retryable** state, not a failure.
- Sign with the wallet, then **verify what came back** before submitting: wallets legitimately add ComputeBudget and Lighthouse instructions (and priority-fee changes); anything else means something changed.
- **Blockhash lifetime is ~60-90s on mainnet and short on devnet (~36s observed).** If a human decides, ask the backend for a fresh blockhash **after** they authenticate, and check that *only* the blockhash changed (same fee payer, accounts, instructions). `Blockhash not found` is the symptom.
- Decode locally and **simulate on the right cluster** before showing anything; never trust the agent's or the backend's description. Check any stated intent against the decoded transaction and escalate mismatches (hold-to-approve).
- Versioned transactions with **address lookup tables cannot be fully decoded offline**; fall back to what is visible (for example a known program id) and say so.
- Jupiter swap parsing: v6 route/sharedAccountsRoute instruction data; parse input/output mints and `minOut` and compare with the claim. Jupiter is mainnet-only (no devnet liquidity), and a new wallet has no mainnet funds to test with.
- Block by default: unknown programs, token `approve`/`setAuthority`/system `assign` (spending authority), amounts over a hard cap or daily cap.
- Libraries: `@solana/web3.js` 1.x works with MWA; use `@noble/hashes` for hashing (`txHash` = lowercase hex SHA-256 of the raw bytes).
- Test on **devnet** first. Use a throwaway wallet. Record signatures and check them on an explorer.

## 7. Backend patterns (Fastify + SQLite)

- Fastify + zod. Return **400** with an `issues` list for validation errors (an unhandled Zod error otherwise becomes 500).
- `@fastify/rate-limit` only applies to routes registered **after** it in the same plugin scope; wrap routes in a child plugin.
- `node:sqlite` is built into Node 22+; bundlers (esbuild/tsup) rewrite the import, so load it at runtime with `process.getBuiltinModule("node:sqlite")` and mark it external.
- Store agent keys and device tokens as **salted hashes**, show them once, decide 401 before anything else, answer 404 for both "missing" and "not yours".
- Idempotency-Key on creating requests; replay returns the original with a header.
- Per-server device identity in the app: when a server no longer recognises the phone (401 after a wipe), re-register once, single-flight (guard against the race), then retry.
- Print a start-up screen and one-line request logs from the CLI launcher only; keep containers quiet by default.
- Docker: `node:24-slim`, build stage + runtime stage, `/data` volume, non-root user, `HEALTHCHECK`, refuse to start in production with the default salt. (Not built or verified in Nod: verify it.)
- OpenAPI file + a test that fails when the spec and the code's routes disagree. Quote YAML descriptions that contain `: `.

## 8. Testing and process

- `vitest` for pure logic (decoding, swap parsing, intent checks, server list, auth planning, filters). Keep logic in pure modules so it is testable; keep screens thin.
- Write a test for every bug you fix, especially device-only ones (Hermes quirks).
- Run `npx tsc --noEmit` and the tests before committing; verify UI changes on the phone with a screenshot.
- Commit in small steps. Say plainly what has been verified, what was only run on devnet, and what has never been run (for example a Docker build).
- Do not call a prototype "battle tested": list what was exercised (one phone, one wallet, devnet) and what was not.

## 9. Common failures, quick map

| Symptom | Likely cause / fix |
|---|---|
| `Blockhash not found` | Refresh the blockhash after user auth; verify only the blockhash changed |
| `-32602 ... identity.icon must be a relative URI` | Use a relative icon path |
| Wallet prompts Connect every time | Phantom needs a verified identity domain |
| `Cannot send in CLOSED` | User backed out; treat as retryable |
| `undefined is not a function` only on device | Hermes difference (`subarray`, Buffer); add a regression test |
| Tap does nothing right after typing | `keyboardShouldPersistTaps="handled"` |
| App fails to install over old one | Different signing key, or lower `versionCode` |
| Release app cannot reach backend | https required; `localhost` does not exist on the phone |
| Push never arrives for others | FCM project mismatch; they need your backend or their own build |
| Gradle hangs downloading | IPv6 flag, manual SDK/NDK download, longer timeouts |
